@ControllerAdvice handles cross-cutting concerns
==================================================================================
🎯 Why do we need @ControllerAdvice?
❌ Without @ControllerAdvice

@RestController
public class UserController {

    @GetMapping("/users/{id}")
    public User getUser(@PathVariable int id) {
        try {
            // logic
        } catch (Exception e) {
            // exception handling
        }
    }
}
Problems:

* Duplicate code

* Hard to maintain

* Not clean

✅ With @ControllerAdvice
@RestController
public class UserController {

    @GetMapping("/users/{id}")
    public User getUser(@PathVariable int id) {
        // only business logic
    }
}

@ControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(Exception.class)
    public ResponseEntity<Object> handleAllExceptions(Exception ex) {
        return new ResponseEntity<>("Error occurred", HttpStatus.INTERNAL_SERVER_ERROR);
    }
}
✔️ Clean
✔️ Centralized
✔️ Reusable

🔁 What Problems Does @ControllerAdvice Solve?
1️⃣ Global Exception Handling

@ExceptionHandler(UserNotFoundException.class)

2️⃣ Validation Errors

@ExceptionHandler(MethodArgumentNotValidException.class)

3️⃣ Global Response Modifications

* Common error structure

* Logging

* Security checks

⚙️ How @ControllerAdvice Works Internally

1. Request → Controller

2. Exception thrown ❌

3. Spring checks:

 * Is there any @ControllerAdvice?

4. If yes:

 * Matching @ExceptionHandler method is called

5. Response returned to client
=====================================

🧩 @ControllerAdvice vs @ExceptionHandler

| Annotation          | Scope                    |
| ------------------- | ------------------------ |
| `@ExceptionHandler` | One controller           |
| `@ControllerAdvice` | All controllers (global) |
=====================================================




What is @ControllerAdvice?

@ControllerAdvice is a Spring annotation used to handle cross-cutting concerns for multiple controllers in one central place.
